# 변재학의 작은 마을

이력서 기반 자기소개를 RPG 마을에서 만나는 한국어 3D 페이지입니다. 캐릭터를 움직여 주민에게 다가가면 소개·기술·경력을 짧은 대화로 읽습니다. 게임을 하지 않아도 **소개 읽기**에서 같은 내용을 확인할 수 있습니다. 원본 이력서와 연락처는 게시하지 않습니다.

## 로컬 실행

다른 개발자·AI를 위한 전체 인수인계는 [context.md](context.md)에 있습니다. 디자인 결정, 검증 범위, 게시 허용 목록, 배포·롤백 절차를 함께 참고하세요.

Node.js 22 이상. 정적 파일과 Three.js 0.180.0의 실행 파일이 저장소에 포함되어 있어 첫 실행에 패키지 설치가 필요하지 않습니다.

```powershell
npm.cmd run dev
# http://127.0.0.1:4173/
npm.cmd test
npm.cmd run build
# 기존 개발 서버를 Ctrl+C로 종료한 후 빌드 결과 확인
node scripts/serve.mjs --dist
```

서버가 이미 실행 중이면 4173을 재사용하세요. EADDRINUSE는 같은 포트에 서버가 있다는 뜻입니다. 이 프로젝트 서버는 파일 변경을 매 요청 반영하므로 브라우저를 새로고침합니다. 빌드 서버를 쓰는 경우에는 다시 빌드해야 합니다.

## 조작과 접근성

- 카메라는 데스크톱·모바일 모두 캐릭터를 가까이 보여 줍니다. 첫 진입에는 약 1.8초 동안 짧게 접근하고, 이동을 시작하면 즉시 탐색으로 전환합니다. 이동 방향을 살짝 앞서 보는 부드러운 추적과 NPC 대화 시 작은 회전·확대를 적용했습니다. 움직임 줄이기에서는 연출·회전 없이 가까운 고정 각도로 위치를 따라갑니다.
- WASD / 방향키: 화면 방향으로 이동. 모바일: 화면 아래 방향 버튼을 누르고 있기.
- NPC에 가까이 가면 이름과 대화 버튼 표시. E 또는 버튼: 대화 열기.
- 대화 중 E: 다음 문단 / 마지막 문단에서 닫기. 이전 버튼으로 되돌아가기. Esc: 닫기.
- 네이티브 dialog로 포커스를 내부에 유지하며 닫으면 시작 버튼으로 돌아갑니다. 대화 중 이동은 멈춥니다.
- 소개 읽기는 이동과 관계없이 사용 가능합니다. WebGL 생성 실패·컨텍스트 손실 시에도 같은 소개를 읽습니다.
- 원형 입장은 실제 장면 준비 완료 후 끝납니다. 건너뛰기는 장식 대기를 없애며, 준비 중에도 글로 읽을 수 있습니다. 같은 탭에서 재방문하면 연출을 생략합니다.
- OS의 reduced-motion 설정과 상단 움직임 줄이기를 지원합니다. 장식 물결·물레방아·걷기 흔들림·입장 카메라를 줄입니다. 모바일의 위치 추적은 이동한 영역을 볼 수 있도록 유지합니다.
- 시작 위치로 버튼은 이동 상태를 초기화합니다. 강은 건널 수 없고 다리 위에서는 이동할 수 있습니다.

## 데이터와 화면 구조

| 파일 | 수정할 내용 |
| --- | --- |
| `src/content.js` | 원본 이력서 기반 경력 기록, 미래 프로젝트 데이터 |
| `src/village-data.js` | 주민 이름·위치·색, 소개 대화 문단, 기술 태그 |
| `src/world.js` | Three.js 장면, 코드로 만든 모델, 카메라, 조명, 입력 |
| `src/movement.js` | 경계, 충돌, 시작 위치, NPC 근접 판정 |
| `src/app.js` | 대화 문단 전환, 읽기 모드, 입장·포커스·접근성 |
| `src/styles.css` | HUD, 로딩, 대화창, 모바일 레이아웃 |
| `assets/` | 선택적 프로젝트 이미지와 Three.js 실행 파일·라이선스 |

대화는 `paragraphs` 배열의 문자열 하나가 한 장입니다. 보통 2~3개 문단으로 짧게 작성하세요. 실제 이력서의 사실을 자연스럽게 풀어 쓰되 확인되지 않은 수치나 성과는 넣지 않습니다. 대화 중 태그와 이미지·링크는 마지막 장에 표시됩니다. 읽기 모드에는 전체 문단과 상세 경력이 함께 나옵니다.

현재 `profile`의 일부 소개 필드는 첫 버전 보존용입니다. 새 마을의 소개 본문은 `village-data.js`, 상세 경력은 `profile.experience`가 기준입니다. 연락 링크는 승인 전까지 비어 있습니다. 공개할 연락처를 추가할 때에는 데이터와 실제 노출 화면을 함께 검토하세요.

## 프로젝트 NPC 추가

`src/content.js`의 `projects` 배열에 다음 구조로 실제 프로젝트를 추가합니다. 제목과 요약이 없는 항목은 숨깁니다. 아래 문구를 실제 자료로 바꾸세요.

```js
{
  title: '실제 프로젝트명',
  summary: '어떤 문제를 맡아 무엇을 구현했는지 설명합니다.',
  role: '실제 담당 역할',
  period: '실제 진행 기간',
  tags: ['실제 사용 기술'],
  npc: { x: -6, z: 6 },
  image: { src: './assets/project-name.webp', alt: '프로젝트 화면 설명' },
  links: [{ label: '소스 코드', url: 'https://github.com/ACCOUNT/REPOSITORY' }]
}
```

프로젝트를 추가하면 NPC, 수집 개수, 읽기 모드가 함께 확장됩니다. `npc`를 생략하면 기본적으로 x=-6+순번×3, z=6에 배치됩니다. 여러 항목은 좌표를 명시해 겹치지 않도록 하세요. 현재 마을의 이동 범위는 대략 x=-10.8~9, z=-9.1~9.5이며 동쪽 강과 건물·나무·벤치 충돌을 피해야 합니다. NPC 사이 간격은 약 3 이상을 권장합니다. 추가 후 실제로 걸어 접근할 수 있는지 확인하세요. 공간을 넘어서는 개수는 마을 확장 또는 추가 구역 구현이 필요합니다.

이미지는 선택 사항이며 영문·숫자·하이픈 이름으로 assets에 저장합니다. 상대경로는 `./assets/`로 시작합니다. 링크는 http, https, mailto만 허용합니다. 텍스트는 HTML로 해석하지 않습니다. 주민 대화를 여러 장으로 세밀하게 구성하려면 `village-data.js`의 기본 주민 객체처럼 `paragraphs`를 작성해 주민 배열에 추가하세요.

## 의존성과 라이선스

모든 캐릭터·건물·나무·지형·물레방아는 코드로 만든 원본 기하입니다. Bruno Simon의 탐색형 포트폴리오 아이디어를 참고했으며 자동차, 모델, 텍스처, 코드, 음원은 복제하지 않았습니다. 외부 모델·폰트·이미지는 사용하지 않습니다.

Three.js는 MIT 라이선스이며 `assets/vendor/THREE-LICENSE.txt`를 함께 배포합니다. 의존성을 재생성할 때만 다음 명령을 실행합니다.

```powershell
npm.cmd ci --ignore-scripts
node scripts/vendor.mjs
npm.cmd run build
```

## 검증

`npm.cmd test`는 미입력 프로젝트 숨김, 링크 프로토콜, 연락처 비노출, 시작 NPC 근접, 건물 충돌·벽 미끄러짐·강/다리·월드 경계를 확인합니다. 실제 화면에서는 다음을 확인합니다.

1. 3D 첫 화면과 로딩 종료, 새로고침 시 연출 생략.
2. NPC 접근 → E → 다음 문단 → Esc → 재열기, 포커스 복귀.
3. 모바일 390×844에서 방향 버튼·대화 버튼·본문 가독성과 가로 넘침.
4. 움직임 줄이기와 OS 모션 감소 설정.
5. 로컬에서 `http://127.0.0.1:4173/?qa=webgl-failure`로 WebGL 실패를 주입해 대체 안내와 소개 읽기를 확인합니다. 이 검증 스위치는 localhost/127.0.0.1에서만 작동합니다.

## GitHub 게시 — 저장소 생성 완료, 업로드 대기

공개 승인을 받아 [bgm5768/portfolio-rpg](https://github.com/bgm5768/portfolio-rpg) 저장소를 생성했습니다. 브라우저 도구의 로컬 파일 업로드 권한이 없어 현재 저장소는 비어 있고 Pages는 미활성 상태입니다. 승인된 업로드 수단으로 아래 허용 목록을 올린 뒤 배포를 이어갑니다. 예상 사이트 주소는 `https://bgm5768.github.io/portfolio-rpg/`이며 아직 배포 완료 주소가 아닙니다. 기존 저장소를 덮어쓰거나 force push하지 않습니다. 새 인증·권한이 필요한 경우 별도로 확인합니다.

```powershell
# 확정된 새 빈 저장소를 만든 뒤에만 실행
 git init -b main
 git config user.name "확인된 작성자"
 git config user.email "확인된 커밋 이메일"
 git add index.html src assets scripts tests package.json package-lock.json README.md context.md .gitignore
 git diff --cached --name-only
 git diff --cached
 git commit -m "Add interactive developer village"
 git remote add origin https://github.com/ACCOUNT/REPOSITORY.git
 git remote -v
 git push -u origin main
```

웹 공개 승인 후 GitHub Pages에서 main/root를 선택하면 정적 소스가 바로 동작합니다. `assets/vendor`와 라이선스를 반드시 함께 올립니다. 저장소의 비공개 여부와 Pages의 공개 범위는 별도 확인하세요. 실제 게시 URL에서 상대경로, WebGL, 모바일 조작을 재검증합니다.

`private-input/`(원본 이력서), `qa/`(검증 산출물), `versions/`(로컬 이전 디자인), `.env*`, `node_modules/`, `dist/`는 Git에서 제외됩니다. 브라우저 업로드는 .gitignore를 적용하지 않으므로 위 git add와 같은 허용 파일만 선택합니다. 연락처·원본 PDF·비공개 메모를 포함하지 않습니다. 배포 후 실제 URL과 커밋을 이 문서와 context.md에 기록하세요. 문제 발생 시 해당 변경을 git revert로 되돌린 후 push하고 Pages 재배포를 확인합니다.
